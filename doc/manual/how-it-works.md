# How it works

The mod has two parts: one decides which strings in a save are display text, and the other finds each string's entry in the game's tables and replaces it with the same entry in the target language.

## Matching text

Each source-language string is looked up in the game's string tables and replaced with the entry of the same id in the target language. The matcher handles:

- exact entries;
- smart-format templates such as `Durability: {0}/{1}`, with their arguments translated recursively;
- text the game concatenated from several entries, such as `Music Cassette - ` + `Stardust` + ` (Corrupted)`;
- multi-line notes built from several entries;
- fixed suffixes the game appends, such as `(99%-99.9% Purity)`.

When several entries share a source string, the entry whose key shares words with the ids next to the text wins. For example `plant_trait_unappetizing_name` wins next to `category: plant_taste`. After that, the more central table wins, then the most common translation.

The matcher lives in `src/Translator.Pure.cs`.

## Choosing what to convert

`src/SaveWalker.cs` decides what is display text. Non-ASCII text is converted in any field that is not an id. ASCII text is converted only in fields the game is known to localize. The allow-list was found by comparing a Chinese save with the tables. Fields such as `subtitle` hold English even in a Chinese save, so they are internal names and stay unchanged. A few fields, such as `displayName`, hold both: people's names, which the game keeps in English, and the names of night services and events, which it shows in the player's language. There English text is replaced only when it is exactly one game entry and not a person's name; a person is recognised by the `name_` id stored with it.

The save classes the walker may visit are listed in `src/KnownTypes.g.cs`, generated by `tools/Closure.cs` from the game DLL.

## Tests

The engine is kept apart from the game and Unity in `src/*.Pure.cs`, which use nothing but plain C#: the matcher in `Translator.Pure.cs` and the save rewriter in `JsonText.Pure.cs`. The code that talks to the game only reads the string tables and the loaded save and passes them on.

`tests/run.sh` runs `tests/PureTest.cs`, which checks the engine on hand-made table entries without the game, Unity or a save: exact entries, templates and their arguments, choosing between entries that share a source string, untranslated text, and rewriting JSON in place. With the game installed it also runs the mod scanner.

`tests/EngineTest.cs` runs the engine outside the game, on string tables exported from the game's bundles and on a real save. For the Chinese save it was developed with:

- Chinese to English: 492 of 492 distinct texts match a hand-checked conversion, and 60,719 of 60,721 strings in the whole save are identical. The 2 differences are intentional: sprite bookkeeping is left alone, and `startLocale` is set by the mod.
- English to Chinese: no Chinese text is lost. The differences are one-to-many cases, where one English line has several Chinese ones, and English names the game also keeps in Chinese saves.

`tests/ScanTest.cs` runs the game's own mod scanner on the built DLL. The result is no capabilities and not refused.
